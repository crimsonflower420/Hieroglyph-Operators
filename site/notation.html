§規格の要点Standardこのサイトでの使い方Use on this site
1根のある順序木。節点は演算子のラベル・項数・娘から成る。葉は字形と語釈。ブラケット形式が正本で、図はそこから生成する。項数は演算子が決め、娘の数が違えば検査器が落とす。Rooted ordered tree; node = operator label + arity + daughters; leaves = glyph + gloss. Bracket form is the source of truth; figures are generated from it. Arity is fixed by the operator; a wrong daughter count fails the checker.data/derivations/rahman.drv の A・B の行。図は tools/derivations.py が生成する。The A and B lines of data/derivations/rahman.drv; figures from tools/derivations.py.
2主要部は機能の木にだけ置き、_H で示す。配置の木には主要部がない。Heads only in the function tree, marked _H; layout trees are headless.限定符（DET）にだけ _H を付ける。Only determinatives (DET) carry _H.
3二つの層：A 配置、B 型付きの機能。葉の番号でつなぎ、食い違いは明記する。Two layers: A layout, B typed function; linked by node ids; mismatches stated.方形の木と記号のはたらきの木。食い違いは MISMATCH として自動で報告する。Quadrat tree and sign-function tree; mismatches reported automatically as MISMATCH.
4木は階層、順序は木の上の名前付きの線形化（WALK）。例外は記録し、木には組み込まない。Tree = hierarchy; order = named linearizations (WALK). Exceptions are recorded, not built into the tree.WALK_write, WALK_read
5並べ替え：(a) 移動（層 B が支持するときだけ）、(b) 線形化の並べ替え。既定は (b) で、WALK_write ≠ WALK_read と記し、TRANSPOSE(honorific) のラベルを付ける。Reordering: (a) movement, only if layer B argues for it; (b) linearization reorder, marked WALK_write ≠ WALK_read with TRANSPOSE(honorific). Default (b).すべて (b)。書記上の並べ替えには TRANSPOSE(graphic) も使う。All (b); TRANSPOSE(graphic) is also used for graphic reorders.
6どの木にも HYPOTHESIS。確かな事実には出典。未決は OPEN。CONJECTURE は使わない。グラントの考えは GRANT'S HYPOTHESIS（グラントの仮説）と明記する。HYPOTHESIS on every tree; attested facts with source; OPEN for unresolved; no CONJECTURE; Grant's ideas credited as GRANT'S HYPOTHESIS.各導出の見出しに表示する。Shown in each derivation's header line.
7主張しないこと：記号の木は統語・Merge・X バー・θ ではない。書き順・読み順は心理的な導出ではない。機能の木は語の形態・意味そのものではない。二つの水準が同じだとは言わない。並行関係は「グラントの承認待ち」の注に置く。Not claimed: glyph trees are syntax / Merge / X-bar / θ; stroke or reading order is a psychological derivation; function tree = word morphology/semantics; the two levels are the same. Any parallel goes in a 'Parallel (for Grant to approve)' note.二層の導出の最後に明記する。Stated at the end of Two-layer derivations.
8相互リンク：一致する箇所では関連ページへリンクする。用語集の共有は任意。Interlinking: link matching pages; an optional shared glossary.漢字のサイトの書き順と歩き順へリンクする。Links to the kanji site's written order vs walk order.

ヒエログリフでの具体化The hieroglyph profile

規格は演算子の名前を ⿰・⿱ など漢字の IDS から取る。ヒエログリフでは、⿰ と ⿱ をそれぞれ横の結合・縦の結合に当て、差し込み・重ね合わせ・カルトゥーシュ・方形の列（LINEk）を加えた。層 B には、補音（CMPL）、限定符による閉じ（CLOSE）、語尾（INFL・PL）、略記（ABBR）などの型を置いた。一覧は二層の導出にある。The standard takes operator names such as ⿰ and ⿱ from kanji IDS. For hieroglyphs, ⿰ and ⿱ are assigned to the horizontal and vertical joiners, and insertion, overlay, cartouche and the quadrat row (LINEk) are added. Layer B gets types for complements (CMPL), closing by a determinative (CLOSE), endings (INFL, PL), abbreviation (ABBR) and others. The full list is on Two-layer derivations.

=== d05
signs: n1 U7 mr | n2 D21 r | n3 A2
A: [LINE2 [⿱ n1 n2] n3]
B: [CLOSE [CMPL2 n1:PHON2 n2:COMPL] n3:DET_H]
read: n1 n2 n3
